# Legacy endpoint, status and schema map

This table maps the pinned implementation, including plugin routes. It does not
assign future operationIds. All paths are relative to the host prefix (Angular
hosts commonly add `/api`). Route enablement and guards depend on composition.

Each JSON pointer identifies the exact schema in [routes.json](routes.json):
append `/body`, `/params`, `/querystring` or `/response/{status}` to inspect the
complete TypeBox-derived JSON schema. The compact field lists below use `?` for
optional properties; optional does not imply nullable. See [semantics](semantics.md).
Nested constraints and serialized fixture bodies remain in the evidence files.

“Observed” includes negative and disabled-profile cases exercised by the replay;
it is not an exhaustive status contract. Every route has at least one successful
fixture. The webhook has no route body schema: raw bytes are verified and parsed
inside the real adapter. Responses for Identity list all required nullable fields.

`route-metadata.json` additionally contains the orphan entry
`POST /auth/refresh-tokens/{userId}` -> `refreshTokens`. It is absent from the
controller inventory and generated OpenAPI; replay returns 404. The three JWT
plugin routes have **no legacy operationId**. The remaining 26 IDs match both
the full generated spec and its simplified operation snapshot.

The generated OpenAPI declares only the success responses shown above. Error
bodies, cookie/rate-limit/native-action headers and host security behavior are
recorded in [http.json](http.json) and explained in [semantics.md](semantics.md).
